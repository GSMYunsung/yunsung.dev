## 개요

8만 명 이상이 이용하는 야구 팬 플랫폼의 전체 구조를 파악하고 유지보수를 담당했습니다. 레거시 코드에서 비롯된 데이터 불일치 문제와 이벤트 추첨 로직의 설계 결함을 발견하고 수정했으며, 수동으로 운영되던 운영 체계 여러 곳을 자동화했습니다.

## 이벤트 추첨 시스템 재설계

**문제** 추첨 시스템 개편 요청을 받아 기존 로직을 분석했습니다. 유저를 외래키로 갖는 별도 테이블에 당첨 횟수가 누적되고, 그 숫자가 높을수록 추첨에서 불리해지는 레거시 정책이 그대로 남아 있어 반복 구매 사용자일수록 오히려 불이익을 받는 역설적인 구조였습니다.

**분석** 기존 가중치 로직에 보정값을 추가하는 방식과 추첨 로직 자체를 재설계하는 방식을 비교했습니다. 보정은 임시방편이라 근본 원인인 정책 자체의 불공정성을 해결하지 못한다고 판단해 재설계를 선택했습니다.

**실행** 기존 당첨 이력 테이블 구조를 깨지 않아야 한다는 제약 속에서, 테이블은 유지한 채 추첨 로직만 모든 티켓 구매자를 동등한 조건으로 포함하도록 교체했습니다.

**결과** 랜덤 추첨 시스템으로 재설계해 공정성을 확보했고, 반복 구매자가 불이익을 받는 이슈를 해소했습니다.

## 추첨 명단 엑셀 업로드 자동화

**문제** 추첨 대상 명단을 관리자가 백엔드 시스템에 직접 수작업으로 입력해야 했습니다. 이틀씩 소요되던 작업으로 이벤트 운영 일정에 영향을 줬습니다.

**분석** 백엔드 관리자 UI 개선과 엑셀 업로드 자동화를 비교했습니다. 기존 운영 방식(엑셀로 명단을 취합)을 그대로 활용할 수 있는 업로드 자동화가 도입 비용이 낮다고 판단해 선택했습니다.

**실행** 다양한 형식의 엑셀 파일이 들어올 수 있다는 제약 속에서, 업로드된 파일을 파싱해 백엔드 서버로 자동 전송하는 구조로 관리했습니다.

**결과** 이틀씩 소요되던 명단 관리 작업이 **한 시간 안에 완료**될 수 있게 됐고, 플랫폼 관계자로부터 직접 긍정적인 피드백을 받았습니다.

## 멤버십 코드 자동 발급

**문제** 관리자가 백엔드 시스템에 멤버십 코드를 직접 입력한 뒤 사용자에게 전달하는 수동 방식으로 운영돼, 가입자가 늘수록 관리자 부담이 커지는 구조였습니다.

**분석** 코드 생성 배치 작업과 가입 시점 자동 생성을 비교했습니다. 가입 즉시 자동 생성·발급하는 방식이 관리자 개입을 완전히 없앨 수 있다고 판단했습니다.

**실행** 코드 중복·유효성 검증이라는 제약을 관리하며 백엔드에서 코드를 자동 생성·발급하는 로직을 구현했습니다.

**결과** 관리자 개입 없이 가입 시 코드가 자동 발송되도록 개선했습니다.

## 신규 이벤트 기능 출시

**문제** 기존 쿠폰 추첨 외에 신규 이벤트 참여 시스템을 추가해달라는 요청을 받았습니다.

**분석** 기존 쿠폰 추첨 시스템을 확장하는 방식과 별도 이벤트 참여 화면을 신설하는 방식을 검토했습니다. 요구사항이 기존 흐름과 달라 별도 화면 신설을 선택했습니다.

**실행** 기존 시스템과의 데이터 정합성을 유지해야 한다는 제약 속에서 JSP 화면을 구현하고 API를 연동했습니다.

**결과** 신규 이벤트 참여 기능을 정상 출시했습니다.

## 트러블슈팅

### 아이핀·PASS 인증 오류

아이핀·PASS 인증이 특정 시점부터 실패하기 시작했습니다.

오류 로그와 응답 코드를 분석해 외부 API 측 문제로 범위를 좁혔습니다. 동작했던 시점과 안 되던 시점을 추적해 비교한 결과, 협업사 내부 인증서 만료가 원인임을 특정했습니다.

협업사에 직접 이슈를 공유해 해결했습니다.

### Google Play 정책 위반 복구

Google Play 정책 위반으로 앱이 스토어에서 내려갔습니다.

개인정보 처리방침 미비가 원인임을 파악했습니다. 수집 항목을 명시하고, UI 접근성을 개선하고, 데이터 보안 설문지를 재작성해 앱을 복구했습니다.

### 티켓 사이트-플랫폼 데이터 불일치 / 포인트 미지급

레거시 코드로 인해 티켓 사이트 정보와 플랫폼 데이터가 불일치했고, 티켓 구매 시 포인트가 정상 지급되지 않는 로직 오류도 있었습니다.

각 케이스의 데이터 흐름을 추적해 원인을 파악하고 수정했습니다.
