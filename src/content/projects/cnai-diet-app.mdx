## 개요

사용자가 음식을 촬영하면 자사 AI가 영양소를 분석하고, 영양사가 해당 데이터를 기반으로 맞춤 식단을 제안하는 서비스입니다. 앱은 기존에 존재했고, 영양사 관리 웹은 프레임워크 선정부터 설계·구현·유지보수까지 전반적으로 진행했습니다.

## 영양사 관리 웹 0→1 구축

**배경** 영양사가 앱 사용자 데이터를 보고 식단을 관리할 수 있는 웹이 전혀 없는 상태였습니다.

**행동 & 결과** Remix를 선택하고 아키텍처를 설계해, 1인으로 3개월 만에 저칼로리 맞춤 영양소 분석, 환자 식사 기록 뷰어, 사용자 설문·관리자 기능까지 15+ 화면을 0→1 구축했습니다. 실제 영양사분들이 쓰는 서비스로 운영됐습니다.

## OTA 배포 전환 — CodePush

**배경** UI 수정마다 앱 스토어 심사를 다시 받아야 해 반영에 3일이 소요됐습니다. 핫픽스가 발생해도 사용자에게 도달하기까지 최소 수일이 걸리는 구조였습니다.

**행동 & 결과** CodePush를 도입해 네이티브 심사 없이 배포 가능한 구조로 전환했습니다. 반영 시간을 **3일 → 5분**으로 줄이고, 핫픽스 대응 주기를 **주 단위 → 당일**로 단축했습니다.

## 자사 AI 전환 및 앱 구축

**배경** 외부 AI 서비스에 의존하던 구조로 API 비용과 외부 연동 리스크가 존재했습니다. React Native 앱도 설계부터 새로 구축해야 했습니다.

**행동 & 결과** 외부 AI 서비스를 자사 AI로 전환해 외부 API 의존성을 제거하고 운영 비용을 줄였습니다. React Native 기반 Android/iOS 앱을 설계부터 구축하고, 30+ QA 항목을 관리하며 유지보수했습니다.

## Storybook 도입

**배경** 앱과 관리 웹을 동시에 개발하면서 동일한 컴포넌트가 두 플랫폼에 반복 사용됐고, 디자이너와 UI 기준을 공유할 수단이 없었습니다. 스타일 회귀가 발생해도 바로 확인하기 어려웠습니다.

**행동 & 결과** Storybook을 도입해 버튼, 인풋, 카드 등 핵심 컴포넌트를 독립적으로 개발하고 각 상태(기본·비활성·에러 등)를 Story로 정의했습니다. 디자이너와 UI 기준을 문서로 공유할 수 있게 됐고, 스타일 회귀도 시각적으로 바로 확인할 수 있어 QA 부담이 줄었습니다.

## 트러블슈팅

### 필터링 속도 5s → 2.5s

영양사 관리 웹의 필터링 응답이 매번 5초씩 걸렸습니다.

Remix `action` 함수는 form 내 모든 필드 변경을 일괄 처리합니다. 필터 조건을 `hidden input`으로 관리하던 구조에서, 조건이 바뀔 때마다 검색 로직이 의도치 않게 중복 실행되는 문제가 원인이었습니다.

`sessionStorage`에 이전 검색 상태를 캐싱해 중복 실행을 차단했고, **필터링 응답 속도를 2.5초로 단축**했습니다.

### 컴포넌트-서버 간 통신 구조

자식 컴포넌트에서 서버와 직접 통신해야 하는 케이스가 있었습니다. Remix의 `action` 없이 Prisma와 직접 통신하면 컴포넌트 구조가 무너지는 문제가 있었습니다.

Remix routes에 경량 API 파일을 분리하고 `axios`로 요청을 라우팅하는 패턴을 정립해, 컴포넌트 구조를 손상시키지 않고 서버 접근 문제를 해결했습니다.
