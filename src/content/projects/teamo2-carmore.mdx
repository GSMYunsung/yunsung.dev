## 개요

누적 다운로드 300만 건, 제휴 렌터카사 600여 개 규모의 렌트카 예약 플랫폼 카모아의 유지보수와 신규 기획 개발을 담당했습니다. Vanilla JS와 Pug 템플릿으로 오랫동안 운영되던 코드베이스를 React로 점진적으로 전환하는 작업을 맡았습니다.

## React 점진적 전환

**문제** Vanilla JS와 Pug 템플릿으로 운영되던 코드베이스는 상태 관리가 여러 곳에 분산돼 같은 필터인데도 서로 다른 상태를 참조하는 문제가 있었고, 이 구조가 신규 기능 개발 속도를 계속 낮추고 있었습니다.

**분석** 전면 재작성과 점진적 전환을 비교했습니다. 전면 재작성은 서비스 중단과 회귀 범위가 너무 커, 컴포넌트 단위로 Pug와 React가 공존 가능한 점진적 전환을 선택했습니다.

**실행** 두 렌더링 시스템이 공존하는 동안 상태 동기화 비용이 발생한다는 트레이드오프를, 커스텀 훅으로 상태를 캡슐화하고 배럴 파일로 진입점을 단일화하는 방식으로 관리했습니다.

**결과** 기본 컴포넌트 10여 개에 동일 패턴을 일관 적용했고, 조건이 바뀌어도 외부 코드를 건드리지 않고 훅과 컴포넌트만 교체하면 되는 구조를 확인했습니다.

## 숙박페스타 이벤트 필터 설계

**문제** 숙박페스타는 이벤트 기간에만 활성화되는 임시 필터로, 언제든 켜고 끌 수 있어야 했습니다. 기존 필터 상태는 커스텀 훅 안에 있었는데 숙박페스타 필터는 그 상태들과 독립적으로 동작해야 했고, 나중에 다른 조건으로 대체될 가능성도 고려해야 했습니다.

**분석** 기존 훅에 조건을 추가하는 방식과 완전히 독립된 훅으로 분리하는 방식을 검토했습니다. 기존 훅에 얹으면 임시 로직이 영구 로직과 얽혀 이벤트 종료 후 제거하기 어려워진다고 판단해 독립 훅 분리를 선택했습니다.

**실행** 독립성과 사용 편의성 사이의 트레이드오프를, 플래그 하나로 활성화 여부를 제어하는 단순한 인터페이스만 노출하고 연관 필터 초기화 같은 복잡한 처리는 훅 내부에 캡슐화하는 방식으로 관리했습니다.

**결과** 필터 컴포넌트는 배럴 파일로 진입점을 단일화해, 조건이 바뀌어도 외부 코드 수정 없이 내부만 교체되는 구조를 실제 이벤트 종료 후 제거 작업에서 확인했습니다.

## 추첨 시스템 재설계

**문제** 추첨 시스템 개편 요청을 받아 기존 로직을 분석했습니다. 유저를 외래키로 갖는 별도 테이블에 당첨 횟수가 누적되고, 그 숫자가 높을수록 추첨에서 불리해지는 레거시 정책이 그대로 남아 있어 반복 구매 사용자일수록 오히려 불이익을 받는 구조였습니다.

**분석** 기존 가중치 로직에 보정값을 추가하는 방식과 추첨 로직 자체를 재설계하는 방식을 비교했습니다. 보정은 임시방편이라 근본 원인인 정책 자체의 불공정성을 해결하지 못한다고 판단해 재설계를 선택했습니다.

**실행** 기존 당첨 이력 테이블 구조를 깨지 않아야 한다는 제약 속에서, 테이블은 유지한 채 추첨 로직만 모든 티켓 구매자를 동등한 조건으로 포함하도록 교체했습니다.

**결과** 반복 구매자가 불이익을 받는 이슈가 해소됐고, 재설계된 로직으로 프론트엔드 API 연동까지 정상 동작을 확인했습니다.

## 트러블슈팅

### 홈 화면과 목록 간 가격 불일치

홈 화면에 표시되는 렌트카 가격이 목록에서 봤던 가격과 달라지는 오류가 있었습니다.

홈은 Pug, 목록은 React로 구성돼 있어 각자 다른 로직으로 가격을 계산하고 있었습니다. Pug는 React 상태를 참조할 수 없어 별도 구현이 유지되던 상황에서, 비즈니스 정책이 바뀌며 두 화면이 서로 다른 시점의 정책을 참조하게 된 게 원인이었습니다.

현재 정책을 기준으로 Pug 쪽 계산 로직을 맞추는 방식으로 해결했습니다. 이 외에도 기존 시스템 내 여러 건의 동작 오류 원인을 분석해 수정했습니다.
